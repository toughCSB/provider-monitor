# Provider Monitor 1.18.4 — 정확성·성능·실행 수명 보완

## 완료 범위

사용자가 구조 검토 후 “성능, 안정성 모두 개선되는 게 확실하면 모두 진행”하도록 요청한 범위에서 확인된 결함과 측정 가능한 최적화를 적용했다. Mac·SV에 설치하고 기존 계정·설정을 보존했다. HOME은 사용자의 “나중에 적용” 답변에 따라 설치를 보류하고 같은 Windows 설치 파일을 준비했다. 새 커밋·push·공개 릴리스는 수행하지 않았다.

## 주요 변경

| 영역 | 변경 및 검증 |
|---|---|
| Claude | Mac·Windows 모두 주간 한도만 있는 정상 CLI 출력을 허용. Windows 등록 계정은 reset 날짜를 해석하고, 연말·연초와 `3pm` 형식도 처리한다. 모르는 시간대는 날짜를 만들어내지 않는다. |
| AGY | 선택한 모델 가족이 없을 때 다른 모델의 숫자·카운트다운을 대신 표시하지 않는다. 일반 요청 수 fallback은 보존한다. Mac·Windows 선택 규칙을 실제 함수와 fixture로 검사했다. |
| OpenCode | `opencode`의 `oc_sk_` console key와 활성 SQLite 저장 항목을 읽는다. 오래된 `opencode-go` 키보다 현재 키를 우선하고 다른 provider 키를 사용하지 않는다. |
| Windows 조회 소유권 | 등록 계정으로 대체된 기본 Codex·Claude polling을 멈추고 등록 해제 시 복귀한다. 이전 generation의 응답은 게시하지 않는다. |
| 재시작 | 관리 계정 캐시는 원 측정 시각·수치·대기 시각을 유지하면서 `stale`로 복원한다. 과거 `ok`를 현재 연결 성공으로 주장하지 않는다. |
| Mac CLI 수명 | 로그인 후 신원 확인, 사용량 조회 및 확인 단계에 취소를 전달한다. 사용량 조회 전체에 30초 예산을 적용하고 이전 단계의 timeout이 다음 프로세스를 종료하지 않게 소유권을 검사한다. |
| Codex 실행 비용 | 한 사용량 조회에 app-server를 세 번 시작하던 것을 한 번으로 줄였다. 같은 실행 안에서 account/read → rateLimits → account/read를 순차 수행하고 전후 파일 신원도 확인한다. 실행 횟수·잘못된 계정 거부·취소를 fake executable을 통해 검증했다. |
| 갱신 수명 | 계정 출처 교체 시 기존 refresher Task를 취소하고 이전 callback과 Combine 구독을 제거한다. 진행 중 작업의 소유권을 다음 timer tick이 덮어쓰지 않는다. |
| Claude 요청 재사용 | Mac 직접 endpoint의 성공 응답을 90초 이내 재사용하고 같은 계정·토큰의 동시 요청을 합친다. 측정 시각을 갱신 시각으로 바꾸지 않으며 계정/토큰 변경·만료 window·429를 분리한다. |
| Windows AGY | loopback 요청에서만 환경 proxy를 제외한다. 조회용 자식에 `AGY_CLI_DISABLE_AUTO_UPDATE=true`를 전달해 조회가 CLI 자체 업데이트를 시작하지 않도록 한다. |
| 설치·업데이트 | Mac의 고정 staging 문자열을 고유한 전용 디렉터리로 바꿨다. Mac DMG·Windows installer를 정확한 버전/파일명으로 선택한다. Windows는 다운로드를 제한 크기로 스트리밍하고 전용 임시 파일을 사용한다. 실패 파일은 즉시, 오래된 자체 installer는 다음 실행에서 정리한다. |
| 검증 진입점 | `make test`와 `make test-ci`에 `make test-ui`를 연결했다. Windows용 `windows/scripts/verify-native.ps1`을 추가하고 삭제된 workflow를 전제로 한 문서를 바로잡았다. |

## 성능 측정

LM Studio의 `LMStudioLogTail.poll()`을 실제 소스로 컴파일하고, 임시 폴더 24개와 로그 4,800개에서 40회 실행했다. 이전 코드는 매번 모든 폴더의 파일을 정렬했으며 수정본은 최신 로그가 있는 폴더까지만 탐색한다.

| 지표 | 이전 | 수정 후 |
|---|---:|---:|
| 반복 조회 중앙값 | 158.138 ms | 0.775 ms |
| p95 | 166.011 ms | 1.008 ms |

이는 **합성 fixture의 로그 탐색 단계** 측정이며 앱 전체 응답 속도나 실제 사용자 로그의 개선 배수를 뜻하지 않는다. 새 월·숫자 순서의 파일 rotation·삭제·변경 없는 파일의 중복 집계 방지를 회귀 검사했다. 초기 이력 읽기는 모든 이력이 필요하므로 보존했다.

## 검증 결과

- Mac 전체: **1,754개 실행, 3개 제외, 실패 0개**. 최종 Debug bundle 전체 `test-without-building` 실행으로 확인.
- Mac CLI 수명 검사: **14개 통과**. 로그인 후 identity 취소, 사용량 중 취소, 전체 deadline 및 Codex 실행 횟수 포함.
- Windows 네이티브 Rust: **176개 통과, 2개 명시적 제외, 실패 0개**.
- 화면 관련 Node 검사 5개 통과: 문법, Mac parity, 관리 계정 렌더링, 로그인 polling, 실제 AGY 선택 함수.
- Mac universal Release(`x86_64 arm64`)와 Windows NSIS 빌드 성공. `git diff --check` 통과.
- 첫 통합 검사에서 AGY 테스트의 이전 다른 가족 fallback 가정을 수정했다. Windows 날짜 파서의 정시 표기와 일반 요청 수 선택도 실패 fixture를 통해 보완했다. 초기 실패를 최종 통과 수치에 섞지 않았다.

Mac 실제 접근성 상태와 스크린샷에서 Claude 1, Codex 1·2, Grok, Antigravity, OpenCode의 링과 퍼센트를 확인했다. 확인 시점 표시값은 각각 99%, 83%, 3%, 98%, 100%, 81%였으며 이후 사용에 따라 달라진다. 등록 Claude·Codex 및 AGY·Grok의 저장된 측정 시각도 설치 후 새 값으로 확인했다.

## 적용하지 않은 변경과 한계

- Grok 직접 refresh-token 갱신 및 `grok models`로 교체하는 대안은 추가하지 않았다. 현재 공식 CLI 갱신이 실제로 동작하며 새 방식의 우월성이 확인되지 않았다.
- Codex ProLite의 별도 rollout 주간 수치 합치기는 현재 관리 계정에서 누락이 재현되지 않아 보류했다. 계정이 다른 로컬 로그를 섞지 않는 것이 우선이다.
- Aside LevelDB 캐시의 광범위한 비동기화는 미측정 상태에서 바꾸지 않았다. 현재 Mac의 Codex 2개·Claude 1개는 관리 CLI 경로를 사용한다. 브라우저 계정 fallback과 삭제 기록 처리는 보존했다.
- 원본 비용 인덱서·새 provider·codex-auth 활성 계정 스위치 기능은 추가하지 않았다. 불필요하다고 입증한 production 파일은 없으며 실제 안전장치와 fallback을 삭제하지 않았다.
- 서버가 인증을 실제로 철회한 경우의 재로그인까지 없애는 변경은 아니다. Windows updater의 공개 산출물 검증은 정확한 출처·파일명·크기를 검사하며, 선택적인 GitHub digest에 대한 암호학적 검증까지 추가한 것은 아니다.
